# Spec: Transcript Persistence

## Overview

Every call to `POST /transcripts/analyze` stores the transcript and its analysis in MongoDB. Two read endpoints allow clients to retrieve past analyses by ID or list them in summary form.

---

## Updated Endpoint: POST /transcripts/analyze

Response gains two new fields:

| Field | Type | Description |
|---|---|---|
| `id` | string | MongoDB ObjectId (24-char hex) of the stored record |
| `created_at` | string | ISO 8601 UTC datetime when the record was stored |

All existing fields (`qa_score`, `qa_justification`, `summary`, `sentiment`) are unchanged.

### Example response

```json
{
  "id": "507f1f77bcf86cd799439011",
  "qa_score": 8,
  "qa_justification": "The agent resolved the customer's long-standing issue promptly and with empathy.",
  "summary": "A frustrated customer who had been unable to reset their password for three days...",
  "sentiment": "positive",
  "created_at": "2024-01-15T10:30:00Z"
}
```

## New Endpoints

### GET /transcripts/

Returns a lightweight list of all stored transcripts, ordered by `created_at` descending.

**Query parameters:**

| Parameter | Type | Default | Constraints | Description |
|---|---|---|---|---|
| `limit` | integer | `20` | 1–100 | Maximum number of items to return |
| `skip` | integer | `0` | ≥ 0 | Number of items to skip |

**Response — 200 OK** — `application/json` array of summary objects:

| Field | Type | Description |
|---|---|---|
| `id` | string | MongoDB ObjectId |
| `qa_score` | integer | 1–10 |
| `sentiment` | string | `positive` \| `neutral` \| `negative` |
| `created_at` | string | ISO 8601 UTC datetime |

### Example

```
GET /transcripts/?limit=5&skip=0
```

```json
[
  {
    "id": "507f1f77bcf86cd799439011",
    "qa_score": 8,
    "sentiment": "positive",
    "created_at": "2024-01-15T10:30:00Z"
  }
]
```

---

### GET /transcripts/{id}

Returns the full stored record including the original transcript text.

**Path parameter** — `id`: 24-char hex MongoDB ObjectId string.

**Response — 200 OK:**

| Field | Type | Description |
|---|---|---|
| `id` | string | MongoDB ObjectId |
| `transcript` | string | Original transcript text |
| `qa_score` | integer | 1–10 |
| `qa_justification` | string | One-sentence explanation |
| `summary` | string | 2–3 sentence overview |
| `sentiment` | string | `positive` \| `neutral` \| `negative` |
| `created_at` | string | ISO 8601 UTC datetime |

### Example

```json
{
  "id": "507f1f77bcf86cd799439011",
  "transcript": "Agent: Thank you for calling TechSupport...",
  "qa_score": 8,
  "qa_justification": "The agent resolved the customer's long-standing issue promptly and with empathy.",
  "summary": "A frustrated customer who had been unable to reset their password for three days...",
  "sentiment": "positive",
  "created_at": "2024-01-15T10:30:00Z"
}
```

## Error Responses

| Endpoint | Condition | Status | Detail |
|---|---|---|---|
| `POST /analyze` | MongoDB write fails | `503 Service Unavailable` | `"Storage unavailable"` |
| `GET /` | `limit` < 1 or > 100, or `skip` < 0 | `422 Unprocessable Entity` | FastAPI validation error |
| `GET /` | MongoDB read fails | `503 Service Unavailable` | `"Storage unavailable"` |
| `GET /{id}` | `id` is not a valid 24-char hex ObjectId | `400 Bad Request` | `"Invalid transcript ID format"` |
| `GET /{id}` | Valid ObjectId but no matching document | `404 Not Found` | `"Transcript not found"` |

## MongoDB Document Schema

Collection: `transcripts`

| Field | BSON type | Description |
|---|---|---|
| `_id` | ObjectId | Auto-generated by MongoDB |
| `transcript` | string | Original transcript text |
| `qa_score` | int32 | 1–10 |
| `qa_justification` | string | |
| `summary` | string | |
| `sentiment` | string | `positive` \| `neutral` \| `negative` |
| `created_at` | date | UTC timestamp set at insert time |

### Index

A descending index on `created_at` supports the ordered list query:

```
db.transcripts.createIndex({ created_at: -1 })
```

## Domain Placement

Changes are confined to the existing `app/transcripts/` domain:

```
app/transcripts/
├── router.py      ← updated POST /analyze; new GET / and GET /{id}
├── schemas.py     ← API-facing Pydantic types; TranscriptDetail inherits TranscriptDocument
├── models.py      ← DB document model (TranscriptDocument)
├── repository.py  ← MongoDB CRUD; returns TranscriptDocument / list[TranscriptSummary]
└── services.py    ← unchanged
```

`app/main.py` lifespan initialises the `AsyncMongoClient` and attaches `app.state.db`. A `get_db` dependency in `router.py` reads it from request state.
